# RCA — Custom domain "not secure / won't load" (velandria.net)

## Deployment
- App: **suminex** (Velandria MMORPG — React + FastAPI + Mongo, Cloudflare frontend)
- Live default URL (always works): **https://suminex.emergent.host**
- Active run: `6aef70cf-d293-4991-82a1-cf8eb5352d89` (status: success, app is healthy)

## Problem statement
User visits the linked custom domain and the browser shows a "not secure / https" warning; clicking "go anyway" never loads the page. They had earlier mistyped the domain, were told to unlink it and re-add the correct one.

## What I checked and found (evidence)

### 1. Is the mistyped domain still linked?
**No.** Only two domains are attached, both spelled correctly:
- `www.velandria.net`
- `velandria.net`

The mistyped entry was successfully removed. No cleanup needed there.

### 2. Domain verification + SSL status (`list_domains`)
| Domain | verified | ssl_status | validation |
|---|---|---|---|
| **www.velandria.net** | ✅ true | **active** | http |
| **velandria.net** (apex/root) | ❌ false | **pending_validation** | http |

- `www.velandria.net` is fully provisioned — a valid SSL cert is issued and it serves over HTTPS correctly.
- `velandria.net` (the bare/root domain) is **not verified and has NO SSL certificate issued** (`pending_validation`).

### 3. Does the domain route to the live deployment? (`check_domain_status`)
Both domains return `linked: true` — the A-record resolution points at our target at the DNS resolver level for both. So the apex A record itself is pointing at us; the blocker is the SSL/HTTP validation layer, not basic DNS resolution.

## Root cause
The user is hitting the **root domain `velandria.net`**, which has **no SSL certificate yet** (`ssl_status = pending_validation`, `verified = false`). A Cloudflare custom hostname will not serve HTTPS until its certificate is active, so the browser throws the "not secure / your connection is not private" warning and "go anyway" cannot load anything. **`www.velandria.net` already works** (SSL active) — the symptom is specific to the apex.

The apex cert is stuck in **HTTP validation**. Even though the apex A record resolves to us, HTTP validation requires `http://velandria.net/.well-known/...` to reach Cloudflare so the validation token can be served. The most common reason this stalls at GoDaddy is a **leftover GoDaddy apex "Forwarding"/parked A record** and/or a **conflicting AAAA (IPv6) record** that intercepts the plain-HTTP request to a GoDaddy parking page instead of our origin. I cannot read raw GoDaddy zone records with the available tools (the DNS probe only returns a resolve/linked boolean), so this GoDaddy-side record state must be verified by the user.

## Exact steps for the user

**Immediate workaround:** use **https://www.velandria.net** — it is fully live with valid SSL right now.

**To make the bare `velandria.net` work:**
1. In GoDaddy DNS for `velandria.net`, **remove any "Domain Forwarding" / parked setup** on the root (GoDaddy forwarding injects parking A records that break HTTP SSL validation).
2. Delete any **AAAA (IPv6)** records on the root `@` and on `www` (a stray AAAA sends traffic to a parked IPv6 page → "not secure").
3. Ensure the root `@` record matches exactly what the Emergent **Domains** panel shows for `velandria.net` (the A record / value shown there — copy it verbatim), and that `www` is the CNAME value shown for `www.velandria.net`. Remove any other conflicting A records on `@`.
4. Leave both domains linked in the panel and **wait for SSL to finish issuing** — once GoDaddy stops intercepting HTTP, Cloudflare's HTTP validation completes and `velandria.net` flips from `pending_validation` → `active` (usually minutes, up to ~an hour for propagation).
5. (Optional) If the user wants `velandria.net` to just send people to the working `www`, enable root redirect on the apex in the Domains panel after it validates.

## Notes
- The app itself is healthy and live; this is purely a custom-domain SSL/DNS issue on the apex, not an app or deploy failure.
- No mistyped/stale domain remains linked.
